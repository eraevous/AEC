# Telosmith without Spec Kit

How to plug Telosmith into an agentic coding setup that has no Spec Kit: Claude Code with a `CLAUDE.md` and hooks,
Cursor or Copilot agents with a rules file, or an in-house orchestrator with CI gates. Everything below was run on
2026-11-04 against `main` at 5650d3f (aec 0.5.0, pip-installed into a fresh venv), in a scratch git project with
no `.specify/` directory. The output is pasted as printed, trimmed only where marked `...`.

Telosmith does not depend on Spec Kit. `aec init` checks only whether `.specify/` exists, and only to print one
extra next step (`src/aec/init.py`, `spec_kit = (root / ".specify").is_dir()`). No other module reads Spec Kit
files; `edges.py` lists `.specify` only as a directory to skip. Details are [at the end](#what-spec-kit-adds-and-what-is-lost-without-it).

## The scratch project

It ships in [`examples/without-spec-kit/`](../../examples/without-spec-kit/): the two source files,
`docs/pricing.md`, the full `.aec/records.jsonl` (its anchor carries the real sha256, and the decision has
`subject: design`, both of which `check` requires), the three scripts below, and `run.sh`, which runs every path on
this page in a temporary repo in about 6 s (`PYTHONPATH=src examples/without-spec-kit/run.sh` from a checkout).
Hashes and short SHAs in `run.sh`'s output differ from those pasted here.

It is a `shop` package with two files. `apply_discount` calls `clamp`, which calls `round_cents`
and reads `LIMIT`; `shop/tax.py` holds `RATE`, `add_tax` and `label`. After `aec init . --owner "Ada"`, these
records were appended (the full lines follow the README's quickstart shape):

- `R-1` is linked to `code:shop.pricing.apply_discount`, with its rationale anchored to `docs/pricing.md` L3-4.
- `R-2` is linked to the module `code:shop.tax`.
- `C-1` depends on `R-1@1`, `E-1` supports `C-1@1`, and `D-1` (accepted, `decided_by: AU-owner`) depends on `C-1@1`.

The same `check` passes in every path below:

```text
aec check: 0 error(s), 0 warning(s) (structural)
```

## Path 1: Claude Code hook (generated by `aec init`)

```bash
mkdir -p .claude && cp .aec/snippets/claude-settings.json .claude/settings.json   # merge if you already have one
```

It is a `PostToolUse` hook on `Edit|Write|MultiEdit` with a 30 s timeout. After each edit it refreshes the
snapshot, runs `check` (exit 2 with the errors when records are broken), snapshots `HEAD` to
`.aec/hook-before.jsonl`, and runs `code-impact --exit-code`. If anything is affected or pointed at, it writes the
report to stderr and exits 2, so Claude Code shows it to the agent. Otherwise it stays silent. The hook was run by
hand, as in [demo.md §4](../demo.md):

```bash
HOOK=$(python3 -c "import json; print(json.load(open('.claude/settings.json'))['hooks']['PostToolUse'][0]['hooks'][0]['command'])")
CLAUDE_PROJECT_DIR=$PWD bash -c "$HOOK"; echo "exit $?"
```

```text
exit 0                                                         # clean tree
...
[finding] structural: code:shop.pricing.apply_discount reaches changed code:shop.pricing.clamp (calls, depth 1); no status change; candidate for attention: R-1@1
0 affected, 5 conclusions with no status change (1 pointer(s) above: candidates for attention)
exit 2                                                         # clamp edited (0.40 s)
...
[stale] R-1@1: Discounts never make a price negative.
[needs_review] C-1@1: Checkout totals are never negative.
[needs_review] D-1@1: Ship the checkout with the never-negative guarantee.
3 affected, 2 conclusions with no status change
exit 2                                                         # apply_discount edited
...
[stale] R-2@1: Tax is computed at the published 8% rate.
exit 2                                                         # RATE edited (module link)
```

Limits: it needs `aec` ≥ 0.5.0 on the agent's `PATH`/`python3` (older versions make the hook exit 1 with a
message, without blocking). It re-reports on every later edit until the change is committed. It reaches one call
by default, so a `LIMIT` edit (two hops from `apply_discount`) printed `0 affected`.

## Path 2: plain git hooks (any agent, any editor)

For agents whose harness has no post-edit hook (Cursor, Copilot agent mode, Codex CLI, an in-house loop), git is
the common surface. Both scripts are POSIX `sh` and need only the Python standard library. They are **report-only
by default**. `TELOSMITH_BLOCK=1` makes them refuse the commit or push when anything is affected. Record errors
always block the commit.

### `.git/hooks/pre-commit`

```sh
#!/bin/sh
# Telosmith pre-commit: check records, then report what the commit's code changes put up for review.
# Report-only by default; set TELOSMITH_BLOCK=1 to refuse the commit when anything is affected.
# Compares HEAD with the working tree (git stash -k first if you need staged-only).
cd "$(git rev-parse --show-toplevel)" || exit 0
[ -f .aec/records.jsonl ] || exit 0
python3 -m aec code-impact --help 2>/dev/null | grep -q -- --exit-code || {
  echo "telosmith pre-commit: installed aec lacks code-impact --exit-code (need >= v0.5.0); skipping" >&2; exit 0; }
python3 -m aec edges . -o .aec/edges.jsonl >/dev/null 2>&1
python3 -m aec check .aec/records.jsonl --edges .aec/edges.jsonl >/dev/null || {
  python3 -m aec check .aec/records.jsonl --edges .aec/edges.jsonl >&2; exit 1; }   # record errors always block
git rev-parse -q --verify HEAD >/dev/null || exit 0                                  # first commit: nothing to compare
python3 -m aec snapshot . --rev HEAD -o .aec/hook-before.jsonl >/dev/null 2>&1 || exit 0
out=$(python3 -m aec code-impact .aec/records.jsonl .aec/hook-before.jsonl .aec/edges.jsonl --exit-code 2>&1) && exit 0
printf '%s\n' "$out" >&2
echo "(Telosmith: stale/needs_review are status changes; structural pointers are candidates for attention.)" >&2
[ "${TELOSMITH_BLOCK:-0}" = 1 ] && { echo "telosmith pre-commit: blocked (TELOSMITH_BLOCK=1); re-check the records above" >&2; exit 1; }
exit 0
```

### `.git/hooks/pre-push`

```sh
#!/bin/sh
# Telosmith pre-push: report what the pushed commits put up for review, against the merge-base with the
# remote's default branch. Report-only by default; TELOSMITH_BLOCK=1 refuses the push when anything is affected.
cd "$(git rev-parse --show-toplevel)" || exit 0
[ -f .aec/records.jsonl ] || exit 0
python3 -m aec code-impact --help 2>/dev/null | grep -q -- --exit-code || exit 0
base_ref=${TELOSMITH_BASE:-$(git symbolic-ref -q --short "refs/remotes/$1/HEAD" 2>/dev/null || echo "$1/main")}
base=$(git merge-base "$base_ref" HEAD 2>/dev/null) || { echo "telosmith pre-push: no merge-base with $base_ref; skipping" >&2; exit 0; }
tmp=$(mktemp -d) || exit 0
trap 'rm -rf "$tmp"' EXIT
python3 -m aec snapshot . --rev "$base" -o "$tmp/base.jsonl" >/dev/null 2>&1 || exit 0
python3 -m aec snapshot . --rev HEAD -o "$tmp/head.jsonl" >/dev/null 2>&1 || exit 0
git show HEAD:.aec/records.jsonl > "$tmp/records.jsonl" 2>/dev/null || exit 0       # the records being pushed
out=$(python3 -m aec code-impact "$tmp/records.jsonl" "$tmp/base.jsonl" "$tmp/head.jsonl" --exit-code 2>&1) && exit 0
echo "telosmith pre-push: vs $base_ref ($(echo "$base" | cut -c1-8))" >&2
printf '%s\n' "$out" >&2
[ "${TELOSMITH_BLOCK:-0}" = 1 ] && exit 1
exit 0
```

Install with `cp pre-commit pre-push .git/hooks/ && chmod +x .git/hooks/pre-*` (or point `core.hooksPath` at a
tracked folder). Tested on branch `feature` off `main`, with a local bare remote:

```text
commit exit 0 (readme only, expect silent)
commit exit 0 (round_cents, one hop from clamp, two from apply_discount)    # silent: depth 1
[finding] structural: code:shop.pricing.apply_discount reaches changed code:shop.pricing.clamp (calls, depth 1); no status change; candidate for attention: R-1@1
commit exit 0                                                                  # clamp edited; 0.45 s
...
[stale] R-1@1: Discounts never make a price negative.
...
telosmith pre-commit: blocked (TELOSMITH_BLOCK=1); re-check the records above
commit exit 1 (blocking mode)
...
telosmith pre-push: vs origin/main (13b185dd)
[stale] R-1@1: Discounts never make a price negative.
[needs_review] C-1@1: Checkout totals are never negative.
[needs_review] D-1@1: Ship the checkout with the never-negative guarantee.

...
error: failed to push some refs to '../origin.git'
push exit 1 (blocking)
```

Notes:
- Pre-push reports the **net** change since the merge-base. The `clamp` pointer from the earlier commit does not
  appear, because `apply_discount` itself changed and the report drops a pointer whose records it already flags
  (code-impact-qual-001, item 1).
- Pre-commit compares the working tree, not the index. Unstaged edits count.
- Who sees it: an agent that runs `git commit` through a shell tool sees the stderr in its tool result. A human
  sees it in the terminal. Whether a given agent reads it and acts on it is **untested**.

### Append-only guard

`check` does not detect a record line that was edited in place. An edited evidence text passed with 0 errors in
this pass. This guard does detect it. Run it in CI, or from pre-push with `"$base_ref"`:

```sh
#!/bin/sh
# Fails when .aec/records.jsonl at HEAD does not start with the bytes it had at the base revision
# (a line was edited, reordered or deleted instead of appended). Usage: append-only.sh <base-rev>
f=.aec/records.jsonl
base=$(git merge-base "$1" HEAD) || exit 0
git cat-file -e "$base:$f" 2>/dev/null || exit 0          # no records at the base: nothing to protect
old=$(mktemp); trap 'rm -f "$old"' EXIT
git show "$base:$f" > "$old"
n=$(wc -c < "$old")
if head -c "$n" "$f" | cmp -s - "$old"; then echo "append-only: ok ($f grew from $n bytes)"; exit 0; fi
echo "append-only: $f no longer starts with its content at $(echo "$base" | cut -c1-8); append a new version instead of editing a line" >&2
exit 1
```

```text
append-only: ok (.aec/records.jsonl grew from 2081 bytes)                     # C-1@2 appended
append-only: .aec/records.jsonl no longer starts with its content at 13b185dd; append a new version instead of editing a line
exit 1                                                                         # C-1@1's text edited in place
```

A merge that keeps both branches' appended lines still passes, because the base's bytes remain a prefix. A merge
that reorders lines fails, which is intended. A byte-identical duplicate line left by a merge is a `check`
warning ([records-hygiene](../reference/records-hygiene.md)).

## Path 3: GitHub Actions job summary (generated by `aec init`)

```bash
mkdir -p .github/workflows && cp .aec/snippets/aec-ci.yml .github/workflows/aec.yml
```

The job runs on `push` and `pull_request`: install, snapshot, `check` (fails the job on record errors), then
`code-impact` against the merge-base, written to `$GITHUB_STEP_SUMMARY`. The impact step never fails the job.
This pass did **not** run it on GitHub's runners. The generated step's script was extracted from the YAML and run
locally, with `GITHUB_STEP_SUMMARY` set to a file and `AEC_BASE` set to `origin/main`. It took 0.16 s and exited 0.
The summary file read:

````text
## Telosmith code-impact (structural, report-only) vs 13b185ddcfea49386d1ab7c08f9fe26452ffddeb
```
# derived 1 change event(s) from the structural diff
# aec impact

- change: revise code:shop.pricing.apply_discount (by code, authorized_by None)

[stale] R-1@1: Discounts never make a price negative.
    via code:shop.pricing.apply_discount -> R-1@1
[needs_review] C-1@1: Checkout totals are never negative.
    via code:shop.pricing.apply_discount -> R-1@1 -> C-1@1
[needs_review] D-1@1: Ship the checkout with the never-negative guarantee.
    via code:shop.pricing.apply_discount -> R-1@1 -> C-1@1 -> D-1@1

3 affected, 2 conclusions with no status change
```
````

Telosmith's own CI runs the same step on every PR, so it has run on GitHub. See code-impact-qual-001's delivery
table.

**Pin gotcha (found here).** Run from a source checkout or a local-path install, `aec init` wrote
`pip install "git+https://github.com/eraevous/Telosmith.git@v0.5.0"`, but on 2026-11-04 the remote has only
`v0.4.0` and `v0.4.1` tags. Until `v0.5.0` is tagged, replace the ref with a commit you have reviewed. A
`pip install git+…@<sha>` makes `init` pin that SHA itself.

For other CI systems (GitLab, Jenkins, an in-house gate), the same script works with `GITHUB_STEP_SUMMARY`
pointed at whatever file the system shows to reviewers, and `AEC_BASE` set to the target branch's SHA. Add the
append-only guard as a separate, failing step.

## Path 4: rules-file text an agent reads

For harnesses that read instructions but run no hooks, or as a companion to a hook so the agent knows what the
output means, paste this into `CLAUDE.md`, `AGENTS.md`, `.cursorrules` / `.cursor/rules/*.mdc`, or
`.github/copilot-instructions.md`:

```markdown
## Telosmith: written reasons attached to code

This repo keeps requirements, claims, evidence and decisions in `.aec/records.jsonl` (append-only JSON lines).
Records link to code as `code:<dotted.name>` (e.g. `code:shop.pricing.apply_discount`).

Before changing a function:
- `grep -n '"code:<module.function>"' .aec/records.jsonl`: read any record that names it.
- `aec reach <module.function> --direction callers --depth 2`: then grep for those callers' names too.

After editing code, run:
    aec edges . -o .aec/edges.jsonl
    aec check .aec/records.jsonl --edges .aec/edges.jsonl
    aec snapshot . --rev HEAD -o .aec/hook-before.jsonl
    aec code-impact .aec/records.jsonl .aec/hook-before.jsonl .aec/edges.jsonl

Reading the output:
- `[ERROR] code-reference ...`: a record points at a name that no longer exists (renamed/moved). Tell the user; do not re-point it yourself unless asked.
- `[stale] ID@N` / `[needs_review] ID@N` / `[unjustified] ID@N`: your change touched code or records this conclusion rests on. Re-read its text, decide whether it still holds after your change, and say which in your summary ("R-1@1 re-checked: still holds because ..."). The tool does not know whether it holds.
- `[finding] structural: X reaches changed Y ... candidate for attention: ID@N`: something one call away changed. Look; you are not obliged to act.
- `0 affected`: nothing linked moved. It does NOT mean the change is safe: unlinked code, dynamic calls and anything two calls away are invisible.

Never edit or delete an existing line in `.aec/records.jsonl`. To change a record, append the same `id` with the next `version`, and re-pin records that depended on the old version. Do not mark a decision accepted; only the authority named in the records can.
```

The four commands in it are the hook's commands, minus the exit-code wiring. They were run in this order in the
scratch project after a `LIMIT` edit, printing `0 affected` (exit 0). They were also run after an `apply_discount`
edit (the stale report above).

**What is not verified:** whether Claude, Cursor or Copilot agents follow this text, how often, or whether it
changes what they report. That is exactly what the
[evaluation draft](../evaluations/eval-design-framework-comparison.md) measures. probe-001 is a caution here:
agents mentioned a briefing in every report that had one, which is not the same as using it.

## What Spec Kit adds, and what is lost without it

Spec Kit adds the extension in [`extension/`](../../extension/) ([spec-kit.md](spec-kit.md)): three optional,
report-only hooks that run at Spec Kit lifecycle points.

| Spec Kit hook | What it does | Without Spec Kit |
|---|---|---|
| after `specify`: `/speckit-aec-purpose-link` | An **agent-executed** prompt (not a CLI command). It collects `id@version` tokens in the active `spec.md`, and reports whether they resolve or point at a superseded version. | **Lost as a step.** There is no spec document to scan and no lifecycle point to hang it on. The nearest equivalent is to ask in the rules file that a PR description cite the `id@version` it serves, and to grep for it. Nothing tests that. |
| after `tasks`: `/speckit-aec-check` | `aec check` against a fresh snapshot | **Same command**, run by the hook, pre-commit or CI instead |
| after `implement`: `/speckit-aec-impact` | `aec edges --diff` + `code-impact` against the previous snapshot | **Same command**, run by the hook, pre-commit, pre-push or CI instead (against `HEAD` or the merge-base) |

Also lost:
- **Spec Kit's artifacts as the place where requirements are written.** With Spec Kit, `spec.md` and its
  acceptance scenarios are a natural source for `requirement` records (`docs/speckit-log.md`). Without it, records
  are written from whatever the team uses (tickets, ADRs, `CLAUDE.md`), or by hand. `import-purpose` still works
  for Codex++ purpose files.
- **Spec Kit's own catching.** On feature 001, "Spec Kit's analyze and converge did most of the catching"
  (`docs/speckit-log.md`, "Honest read"). That was Spec Kit's value, not Telosmith's, so a framework without it
  loses that whether or not Telosmith is added.

Not lost: `init`, `check`, `impact`, `code-impact`, `edges`, `snapshot`, `diff`, `reach`, `fan`, `unresolved`,
`source`, `import-purpose`, the generated hook and CI snippets, and every disposition. Every path on this page ran
with no `.specify/` directory present.

**Record-level tension (for Zach; not resolved here).** `AEC-P0@1` and `AEC-R3@1` name Spec Kit as the frame and the
baseline. A no-Spec-Kit primary evaluation (Zach, 2026-11-04) is a different baseline. See the closing section of
[use-cases.md](../use-cases.md).
